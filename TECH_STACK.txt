1. ARCHITECTURE OVERVIEW & SYSTEM TOPOLOGY
================================================================================
GrabPic is engineered as a three-tier microservice architecture:

[Browser Client]  <--- HTTP (5173/5175) --->  [Nginx / Vite Web Server]
       |                                                 |
       | REST (Multipart/JSON)                           | Proxies /api/*
       v                                                 v
[Spring Boot 3.3.5 Backend API Gateway (Port 8080)]
       |
       | Internal Bridge (HTTP REST / Multipart)
       v
[FastAPI AI Microservice (Port 8000 / 8005)]
       |
       +---> [InsightFace Buffalo_L (SCRFD Face Detector + ArcFace ResNet-50)]
       +---> [FAISS (Facebook AI Similarity Search) - IndexFlatIP]
       +---> [Local Storage Engine (Fast Disk Fallback)]
       +---> [Azure Storage Blob Cloud Service (Optional Hybrid Cloud)]

5. STORAGE & VECTOR SEARCH PERSISTENCE ENGINE
================================================================================
Location: In-Memory, Disk (/app/data/events), & Cloud Blob Storage

- Vector Search & Indexing Engine:
  * FAISS (Facebook AI Similarity Search - faiss-cpu v1.13.2):
    - Index Type: faiss.IndexFlatIP (Exact Inner Product / Cosine Similarity)
    - Vector Dimensionality: 512-D
    - Metric: Inner Product (Dot Product) combined with L2 Normalization
    - Persistence: faiss.write_index / faiss.read_index to disk (faces.index)

- Event Metadata Store:
  * JSON-based Document Cataloging (meta.json):
    - Maps FAISS internal contiguous integer IDs to original image filenames
    - Tracks event creation timestamps and expiration deadlines (expiresAt)
    - Status tracking file (status.json: "processing" -> "completed" / "failed")

- File Storage Systems (Dual-Write Pattern):
  * Local Disk Storage:
    - High-throughput direct file writes to /app/data/events/{eventId}/images/
    - Streaming direct ZIP downloads via Python zipfile & io.BytesIO
  * Azure Blob Storage (Cloud Hybrid Mode):
    - azure-storage-blob (v12.28.1 Java / v12.24+ Python)
    - Non-blocking background uploads (FastAPI BackgroundTasks)
    - Container Structure: events/{eventId}/images/{uuid}.jpg

6. SECURITY, AUTHENTICATION & CRYPTOGRAPHY STACK
================================================================================
- HMAC-SHA256 Signed URLs (Stateless Zero-Trust Image Protection):
  * Prevents unauthorized enumeration and scraping of private event images
  * Signature Structure:
    Payload   : {eventId}:{filename}:{expiryTimestamp}
    Signature : HMAC-SHA256(Payload, secretKey)
    Token     : Base64Url(Payload) + "." + Base64Url(Signature)
  * Constant-Time Verification: hmac.compare_digest avoids timing attacks

- Azure Shared Access Signatures (SAS):
  * Delegated read-only access with strict 10-minute time bounds
  * Custom Content-Disposition headers for direct browser downloads

- Denial-of-Service (DoS) Defense & Rate Limiting:
  * In-Memory Sliding-Window IP Rate Limiter:
    - Limit: 60 image requests per minute per client IP address
    - Purges expired timestamps dynamically on each invocation

- Event Time-to-Live (TTL) Auto-Garbage Collection:
  * Autonomous background scheduler runs every 10 minutes in FastAPI
  * Compares current epoch timestamp against event expiration deadline
  * Performs cascading deletion: Azure Blob Storage + Local Disk Storage

- Strict Cross-Origin Resource Sharing (CORS):
  * Regex-validated origin matching: ^https?://(localhost|127\.0\.0\.1)(:\d+)?$
  * Supports OPTIONS preflight, HEAD, GET, and POST across all dev ports

7. MATHEMATICAL FORMULATIONS & CORE ALGORITHMS
================================================================================
1. L2 Vector Normalization:
   For any 512-dimensional embedding vector v:
   v_norm = v / ||v||_2 = v / sqrt(sum(v_i^2))
   Ensures that Euclidean distance monotonically maps to Cosine Similarity.

2. Cosine Similarity via Dot Product:
   cosine_similarity(A, B) = A_norm . B_norm = sum(A_i * B_i)
   Range: [-1.0, 1.0]. A score of 1.0 denotes identical facial geometry.

3. Multi-Selfie Fusion (Max-Score Aggregation):
   When an attendee uploads k selfies (k in [1, 4]) captured at various angles:
   Fused_Score(Image_M) = MAX_{i=1..k} [ Search(Selfie_i, Image_M) ]
   Mitigates variations in lighting, head pose, facial expressions, and eyewear.

4. Dual-Tier Confidence Thresholding:
   - Strong Match : Cosine Similarity >= 0.65 (High confidence / Primary matches)
   - Weak Match   : 0.50 <= Cosine Similarity < 0.65 (Partial occlusion / Crowd)
   - Discard      : Cosine Similarity < 0.50 (False positive rejection)
